## 1. Overview and Purpose of Version Control

Version control is an indispensable software engineering discipline. For Give-AID, **Git** provides:
1. **Traceability:** A chronological history of every architectural decision, requirement change, and code milestone.
2. **Safety Net (Checkpoints):** The ability to create stable checkpoints before implementing complex features. If an error occurs, you can compare changes or roll back cleanly without losing working code.
3. **Redundancy & Off-Site Backup:** When connected to a private remote repository (e.g., GitHub), your project is protected against local hardware failures, disk corruption, or accidental deletions.

## 3. `.gitignore` Configuration Decisions

A dedicated `.gitignore` file has been established at the project root (`d:\Give-AID NGO\.gitignore`). It enforces strict exclusion rules:

1. **Build Artifacts Excluded:** `bin/` and `obj/` directories are ignored. These contain compiled DLLs, executables, and temporary build caches generated by MSBuild/Roslyn. Storing them in Git causes bloat and merge conflicts.
2. **IDE & User Settings Excluded:** `.vs/` hidden cache and `*.user` files are ignored. These store local window layouts and machine-specific developer settings.
3. **Database Files Excluded:** `*.mdf`, `*.ldf`, and `*.ndf` files are excluded. SQL Server locks these files while running, which corrupts Git operations and exposes raw database binaries.
4. **Secrets & Keys Excluded:** `*.local.json`, `.env`, and private key formats (`*.pfx`, `*.key`) are excluded to guarantee zero disclosure of passwords or API tokens.
5. **Project Files Preserved:** All source code (`.cs`), Razor views (`.cshtml`), web static assets (`wwwroot/`), documentation (`docs/`), and task files (`tasks/`) are tracked.

## 4. Local Checkpoint Workflow

Every time a task from the Give-AID roadmap is completed, execute the following standardized workflow:

### Step 4.1: Inspect Changes
```powershell
git status
```
*Purpose:* View modified, newly added, or untracked files. Verify that no binary build outputs (`bin/`, `obj/`) or private settings appear in the untracked list.

### Step 4.2: Stage Specific Files
```powershell
git add .
```
*Purpose:* Stages verified files into the Git index for the upcoming commit.

### Step 4.3: Commit with Meaningful Message
```powershell
git commit -m "feat(task-03): initialize repository, gitignore, and backup documentation"
```
*Purpose:* Creates an immutable, cryptographic snapshot of your project state.

## 5. Private GitHub Remote Backup Guide

Setting up a remote GitHub repository provides secure cloud backup. Follow these exact steps:

### Step 5.1: Create a Private Repository on GitHub
1. Log into your account at [github.com](https://github.com).
2. Click the **+** icon in the upper right corner and select **New repository**.
3. Repository name: `Give-AID-NGO`
4. Visibility: Select **Private** (Crucial: Keep academic eProjects private to adhere to academic integrity guidelines).
5. **Do NOT** initialize with a README, .gitignore, or license (we already have them locally).
6. Click **Create repository**.

### Step 5.2: Link Local Repository to GitHub
Copy your repository URL (e.g., `https://github.com/amnas2373/Give-AID-NGO.git`) and run:
```powershell
git remote add origin https://github.com/<your-username>/Give-AID-NGO.git
git branch -M main
```

### Step 5.3: Push Local Checkpoint to GitHub
```powershell
git push -u origin main
```
*Note:* Visual Studio or Git for Windows will prompt you to authenticate securely via your browser (OAuth). Never share personal access tokens (PAT) or passwords in chat.

## 7. Strict Safety Guardrails

- **Destructive Commands Prohibited:** Never run `git reset --hard`, `git clean -fd`, or forced pushes (`git push --force`). If an error occurs, inspect `git status` or ask for assistance.
- **Credential Protection:** Never stage or commit database passwords, API secret keys, or credit card simulations with real data.
